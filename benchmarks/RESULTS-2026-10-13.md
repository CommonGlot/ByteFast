# ByteFast benchmark checkpoint (2026-10-13)

Status: **prototype only**. GitHub Actions passed the C++ byte feature tests and end-to-end train/save/load/test/predict workflows.

## Setup

GitHub-hosted Ubuntu runner, C++17 at `-O3`. Tiny synthetic dataset: 120 train lines, 30 held-out lines, English/French/Spanish templates. Inference repeats the same 30 test texts 350 times for 10,500 lines. Model settings: 4,096 embedding buckets, dimension 32, 15 epochs, learning rate 0.3. Byte n-grams 2–5. No attention or convolution.

## Latest observed performance (single run)

| System | Held-out accuracy | 10,500-line prediction |
| --- | ---: | ---: |
| Original fastText (-minn 2 -maxn 5) | 30/30 | 0.02 s (rounded external CLI wall time) |
| ByteFast, 1 hash, no position features | 30/30 | 0.024865 s internal inference = 422,279 docs/s |
| ByteFast, 2 hashes + 4 position bins | 30/30 | 0.087058 s internal inference = 120,610 docs/s |

Results sourced from the GitHub Actions run at [CI #38470874123](https://github.com/CommonGlot/ByteFast/actions/runs/38470874123). ByteFast's `bench` excludes model loading and output printing; fastText's shell timing includes model loading and startup, so absolute numbers are **not directly equivalent**. The dataset is extremely small and repetitive, the times are short, and this is not a reliable estimate of real-world CPU performance.

### Findings

- All three models learn these toy templates. No accuracy advantage demonstrated.
- Multi-hash + positional features add substantial computational cost in this version; do **not** enable them by default.
- Incremental rolling FNV hashing works with the CI tests, but this particular run does not establish a throughput gain. Variability and other bottlenecks need profiling.
- GlotLID vs ByteFast on CommonLID **has not been measured**.

## Before any full GlotLID retraining

1. Implement out-of-core streaming/shuffling, balanced sampling and reliable held-out evaluation.
2. Test individual ablations: one hash, two hashes alone, positions alone, both.
3. Compare on the same actual labeled multilingual documents with matched language inventory and strict macro F1.
4. Benchmark on dedicated CPU hardware with repeated trials, input-length buckets, peak RSS and model download size.
5. Require a reproducible quality/throughput improvement before choosing advanced features.
