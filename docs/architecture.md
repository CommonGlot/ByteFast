# ByteFast architecture and ablations

ByteFast is a general-purpose text classifier. Language identification is
one of the tasks it is tuned on, but nothing in the library is specific to
languages: labels, feature types and normalization are all generic.

## Model

For an input text, ByteFast collects a list of feature ids, averages their
embeddings into one `dim`-dimensional vector, and applies a linear layer and
a loss (softmax by default). This is the fastText supervised model; ByteFast
changes which features go into the average.

```
text ──► fold ──► tokens ──┬─► word ids (vocabulary)                 ─┐
                           ├─► hashed OOV words      (-hashWords)     │
                           ├─► subword n-grams       (-minn/-maxn)    ├─► mean ─► linear ─► loss
                           ├─► word n-grams          (-wordNgrams)    │
                           └─► " w1 w2 … wn " ──┬─► byte n-grams (-minb/-maxb)  │
                                                └─► char n-grams (-minc/-maxc) ─┘
```

All hashed features share one table of `-bucket` rows after the vocabulary
rows. Byte, character and hashed-word features use their own hash function
(FNV-1a over unsigned bytes with a per-feature seed and a murmur3 finalizer).
Identical text therefore lands in different rows for different feature
kinds, and power-of-two bucket counts still use well-mixed bits. The fastText
word and subword hashes are unchanged, so fastText models keep working.

### Design decisions

- **Text n-grams cross word boundaries.** The tokens of a line are joined by
  single spaces and padded with one space on each side. Repeated whitespace
  and tabs therefore do not create features. Labels are never part of the
  text.
- **Character n-grams count UTF-8 characters.** A byte 5-gram covers 5 ASCII
  letters but only about 2.5 Cyrillic or Arabic characters and fewer than 2
  CJK or Devanagari characters. `-minc/-maxc` gives every script the same
  context length; `-minb/-maxb` is cheaper and never fails on malformed
  input. Which works better is an ablation, not an assumption.
- **Lowercasing is one-to-one.** The CommonLID-style normalization of
  `-normProb` uses the simple lowercase mapping of each code point (table
  generated by `tools/gen_unicode_fold.py`).
- **`-maxBytes`** limits only the text n-grams, and cuts at a character
  boundary. Word features always see the whole line.
- **Vocabulary control.** `-minCount` (frequency), `-wordlist` (a given
  vocabulary) and `-maxVocab` (top-N by frequency, ties broken by the word)
  can be combined. `-hashWords` gives every other word a hashed vector, so
  the vocabulary decides which words get their own row, not which words are
  seen.
- **Training-only options.** `-cropProb/-cropMin/-cropMax/-cropUnit` and
  `-normProb` change
  what a training step sees, never prediction. `-inputModel` reloads the
  dictionary, features and weights of a supervised model and only takes the
  training schedule from the command line; the learning-rate schedule is
  computed from the new input's token count.
- **File format.** Models are safetensors files (`format` = `bytefast`,
  `format_version` = `1` in the metadata). The settings are `args.*`
  metadata strings, the vocabulary is three tensors (`vocab.strings`,
  `vocab.counts`, `vocab.types`, plus `vocab.prune` after `quantize
  -cutoff`), and the matrices are `input` and `output`, or their product-
  quantized codes and centroids (`input.codes`, `input.pq.centroids`, ...).

## Ablations

Each axis is a set of flags; nothing else changes between runs.

| Axis | Variants |
| --- | --- |
| A. Input units | words; subwords (`-minn 2 -maxn 5`); text bytes (`-minb 1..2 -maxb 4..6`); text characters (`-minc 1..2 -maxc 3..5`); combinations |
| B. Word vectors | none (`-minCount` > corpus); `-minCount` 1 / 5 / 100 / 1000; `-maxVocab` 50k / 200k / 1M; `-wordlist` (frequency or class-discriminative lists); with and without `-hashWords` |
| C. Word context | `-wordNgrams` 1 / 2 |
| D. Normalization | `-normProb` 0 / 0.3; `-maxBytes` 0 / 256 / 512 |
| E. Capacity | `-bucket` 2^18 / 2^20 / 2^22 × `-dim` 32 / 64 / 128 / 256 |
| F. Loss | `softmax` / `one-vs-all` / `hs` |
| G. Compression | `quantize` with `-cutoff`, `-qnorm`, `-qout`; accuracy against model size |
| I. Short inputs | `-cropProb` 0 / 0.3 / 0.7 with `-cropUnit char` (`-cropMax` 20) or `word` (`-cropMax` 5); from scratch, or as a second stage with `-inputModel` |

Training settings (`-epoch`, `-lr`, `-thread`) are tuned per variant on the
development split with the same search budget for every variant, including
the fastText baseline.

### Evaluation protocol

- **Tasks.** At least one language identification benchmark and at least one
  topic or sentiment benchmark, so that defaults are not chosen for a single
  task:
  - language identification: WiLI-2018 for quick runs; the GlotLID corpus
    with FLORES-200 and UDHR at full scale
  - topic and sentiment: DBpedia, AG News, Yelp
    (`benchmarks/prepare_classification.py` builds WiLI, DBpedia and AG News)
- **Splits.** Choose on a development split. Report the test split once per
  final configuration.
- **Quality.** Macro F1 and accuracy, per-class F1, and false positive rate
  where class prevalence is skewed. Also robustness views: short prefixes,
  changed letter case, noise.
- **Cost.**
  - training time and threads
  - model size and peak memory
  - load time and warm prediction throughput, reported separately (a CLI run
    over a few thousand lines mostly measures model loading)
- **Baselines.** The fastText recipe for the task on the same data, plus a
  size-matched fastText with the same `-bucket`, `-dim` and vocabulary budget.
  Otherwise a large word table can look like an architecture effect.
- **Seeds.** At least three seeds for anything that changes a default.
